# OpenRouter: Variant Cleanup + 24h Auto-Refresh

Two related fixes for big-AGI on OpenRouter:

1. **Variant overload** - dedupe/curate the ~290 models OR returns so users see a
   useful ~40-60 shortlist and the `~`-prefixed "stable latest" aliases are
   promoted to first-class entries.
2. **Stale catalog** - the existing `hashLlmReconfig` gate means a browser
   *never* re-fetches OR models in steady-state production. Add a 24h TTL
   refresh that is **scoped to OpenRouter only**, lives in its own file, and is
   user-toggleable via a new UX Labs row (opt-out, default on).

Design constraint: minimize upstream-facing surface so this rebases cleanly on
`enricoros/big-AGI` `main`.

---

## Verified findings (read-only investigation, completed)

### Claim 1: variant overload - confirmed, scope narrower than originally framed

Live `/api/v1/models` returns ~290 models. Today's noise sources, in order:

- **Dual Anthropic rows.** `openRouterInjectVariants`
  (`src/modules/llms/server/openai/models/openrouter.models.ts:298-328`) splits
  every reasoning-capable Anthropic model into `(thinking)` + base. Working as
  intended; leave alone.
- **Dated snapshots** within visible vendors (`openai/gpt-4o-2024-05-13`,
  `-08-06`, `-11-20`, `gpt-4o-mini-2024-07-18`, `gpt-4-1106-preview`,
  `gpt-4-0314`, `gpt-3.5-turbo-0613`, `qwen/qwen-plus-2025-07-28`, ...). Only a
  tiny `orOldModelIDs` blocks any of these today.
- **`:free` duplicates** of paid models (~14 IDs ending in `:free`). Currently
  flagged only with a `🎁` badge in the label.
- **`-preview` IDs** (`google/gemini-3.1-pro-preview`,
  `gemini-2.5-pro-preview-05-06`, `gemini-3.1-pro-preview-customtools`, ...)
  shown alongside their stable siblings when present.
- **`~`-prefixed stable aliases** (`~anthropic/claude-opus-latest`,
  `~openai/gpt-latest`, `~google/gemini-flash-latest`, ...) - these are exactly
  the "which one do I pick" answer, but today they fail the
  `orModelFamilyOrder` check and get auto-`hidden:true`
  (`openrouter.models.ts:267-269`). User decision: **promote them to visible
  "latest" entries.**
- **Outdated parts of the original complaint:** `is_moderated` was removed from
  the wire schema (`openrouter.wiretypes.ts:51`); no `:online` or
  `self-moderated` IDs appear in the current response. No work needed for these.

### Claim 2: stale model list - confirmed exactly as described

End-to-end trace:

1. `src/modules/backend/backend.router.ts:23-35` computes `hashLlmReconfig` from
   `Release.Monotonics.Aix + Release.TenantSlug + sorted *_API_* envs`. Nothing
   in this set changes when OpenRouter adds a model.
2. `src/common/providers/ProviderBackendCapabilities.tsx:85-89` fetches
   capabilities with `staleTime: 6h` - capabilities refresh, hash does not.
3. `src/common/logic/reconfigureBackendModels.ts:22-33` early-exits if either
   the per-session `_isConfigurationDone` flag is set OR
   `lastLlmReconfigHash === backendReconfigHash` (persisted via
   `store-logic-sherpa.ts:23,37` under `app-state` localStorage).
4. **Effect:** once a browser has reconfigured against a given backend hash, it
   never calls `llmsUpdateModelsForServiceOrThrow` again. Only escape hatches:
   user-initiated *Models -> Refresh*, a backend deploy bumping
   `Release.Monotonics.Aix`, or wiping localStorage.

There is no server-side cache of OR's `/v1/models`; the bottleneck is purely
the client-side hash gate.

## Design principles (apply to every change below)

- **Do not touch shared abstractions.** No new field in `IModelVendor`, no new
  field in `DModelsService`, no edits to `reconfigureBackendModels` /
  `hashLlmReconfig` / `store-logic-sherpa`. Those are load-bearing and the
  primary upstream conflict surface.
- **One new file owns the auto-refresh feature** end-to-end. External code
  touches it via a single function call.
- **Timestamp lives in plain `localStorage`** under a dedicated key
  (`or-models-last-fetch`), not inside the Zustand LLMs store. Avoids
  partialize/migration work on the chat/LLMs persisted blobs.
- **Settings toggle goes in UX Labs**, the small self-contained store and
  panel. Opt-out (default true).
- **Each commit is independently revertable** and individually rebaseable.

## Track A - Variant deduplication (OpenRouter file only)

### A1. Promote `~`-prefix aliases to visible "stable latest" entries

In `src/modules/llms/server/openai/models/openrouter.models.ts`:

- Add `const orLatestAliasPrefix = '~' as const;`.
- In `openRouterModelFamilySortFn`: if an id starts with `~`, strip it for the
  prefix lookup so `~anthropic/...` sits inside the `anthropic/` group, then
  bias to sort before its non-aliased siblings (e.g. by returning a negative
  delta when the alias flag differs).
- In `openRouterModelToModelDescription`:
  - Detect `model.id.startsWith('~')` early.
  - For aliases: append ` · latest` to the label and prefix the description
    with `Stable alias - tracks the latest version. `.
  - Override the `hidden` computation at line 268-269 so aliases are **not**
    hidden by the "not in known families" rule. Easiest: change that rule to
    `!isLatestAlias && (orOldModelIDs.some(...) || !orModelFamilyOrder.some(...))`.
- No changes elsewhere.

### A2. Sibling-aware suppression for `:free` and dated snapshots

Add to the OR file:

```ts
function _canonicalize(id: string): string {
  return id
    .replace(/-\d{4}-\d{2}-\d{2}$/, '')   // -2024-08-06
    .replace(/-\d{4}$/, '')               // -1106, -0314
    .replace(/-preview(-\d{2}-\d{2})?$/, '');
}

export function openRouterPostProcess(models: ModelDescriptionSchema[]): ModelDescriptionSchema[] {
  // canonical ids of currently visible models
  const visibleCanonicalIds = new Set(
    models.filter(m => !m.hidden).map(m => _canonicalize(m.id)),
  );
  for (const m of models) {
    if (m.hidden) continue;
    // :free with a paid sibling -> hide
    if (m.id.endsWith(':free')) {
      const paidId = m.id.slice(0, -':free'.length);
      if (visibleCanonicalIds.has(paidId)) m.hidden = true;
      continue;
    }
    // dated snapshot or preview with a stable sibling -> hide
    const canon = _canonicalize(m.id);
    if (canon !== m.id && visibleCanonicalIds.has(canon)) m.hidden = true;
  }
  return models;
}
```

In `src/modules/llms/server/listModels.dispatch.ts` at the `'openrouter'` case
(lines 522-528), replace the trailing `.reduce(openRouterInjectVariants, [])`
with the same chain wrapped in `openRouterPostProcess(...)`. That's the single
line touched outside the OR file.

Edge cases the code already handles correctly:

- Preview *without* a stable sibling stays visible.
- `:free` *without* a paid sibling stays visible (and still gets the `🎁` badge
  added earlier in the existing label code).
- Anthropic `(thinking)` injection runs before this pass, so both rows survive
  the dedupe (their ids carry `::thinking`, which is not produced by
  `_canonicalize`).

### A3. Modest expansion of `orOldModelIDs`

### A4. Out of scope (explicitly skipped)

- Picker UI grouping changes - once visible count drops to ~40-60, the existing
  flat sort is fine.
- Touching `openRouterInjectVariants` - the Anthropic split is intentional.

## Track B - OpenRouter-only 24h auto-refresh

### B1. New self-contained file: `openrouter.refresh.ts`

Location: `src/modules/llms/vendors/openrouter/openrouter.refresh.ts` (next to
`openrouter.vendor.ts`).

Responsibilities (entire feature lives here):

- Constants: `STORAGE_KEY = 'or-models-last-fetch'`, `TTL_MS = 24 * 60 * 60 * 1000`.
- `_readLastFetch()` / `_writeLastFetch(now)` - localStorage with try/catch.
- Exported `maybeRefreshOpenRouterModels()`:
  1. Bail if SSR (`typeof window === 'undefined'`).
  2. Bail if the UX Labs toggle is off (`getLabsAutoRefreshOpenRouter() === false`).
  3. Bail if `Date.now() - lastFetch < TTL_MS`.
  4. Find the OR service (`llmsStoreState().sources.find(s => s.vId === 'openrouter')`);
     if none, write the timestamp and return (avoids tight-loop on missing service).
  5. `await llmsUpdateModelsForServiceOrThrow(orService.id, true)` - `keepUserEdits: true`
     preserves user pinning/customization.
  6. On success: write timestamp. On error: log warning, do **not** write
     timestamp (so next boot retries).

Imports kept minimal: `llmsStoreState` from the LLMs store,
`llmsUpdateModelsForServiceOrThrow` from `llm.client`, and the UX Labs getter.

### B2. UX Labs toggle (opt-out, default on)

In `src/common/stores/store-ux-labs.ts`:

- Add field + setter:
  ```ts
  labsAutoRefreshOpenRouter: boolean;
  setLabsAutoRefreshOpenRouter: (v: boolean) => void;
  ```
- Default `true` in the store initializer.
- Add a top-level getter at the bottom of the file (mirroring the existing
  `getLabsHighPerformance` / `getLabsLosslessImages` pattern):
  ```ts
  export function getLabsAutoRefreshOpenRouter() {
    return useUXLabsStore.getState().labsAutoRefreshOpenRouter;
  }
  ```
- Bump persisted `version` from 1 -> 2, and add a `migrate` that defaults the
  new field to `true` for existing users (so opt-out semantics are honored even
  on already-installed clients).

In `src/apps/settings-modal/UxLabsSettings.tsx`:

- Pull the new field/setter from `useUXLabsStore()`.
- Render a `FormSwitchControl` row (same component used by surrounding rows),
  e.g.:
  ```tsx
  <FormSwitchControl
    title={<>OpenRouter Auto-Refresh</>}
    description={labsAutoRefreshOpenRouter ? 'Every 24h' : 'Manual only'}
    tooltip="Periodically refresh the list of OpenRouter models in the background (once every 24h, at app start). Disable to keep your current list fixed until you press Refresh in the Models modal."
    checked={labsAutoRefreshOpenRouter} onChange={setLabsAutoRefreshOpenRouter}
  />
  ```
- Place it adjacent to the existing rows; no icon required (or reuse a neutral
  one already imported, e.g. `SpeedIcon`).

### B3. Single-line wire-up in `ProviderBootstrapLogic.tsx`

Modify the existing autoconf effect:

```ts
React.useEffect(() => {
  if (!launchAutoConf) return;
  void sherpaReconfigureBackendModels()
    .then(() => maybeRefreshOpenRouterModels());   // <- only new line
}, [launchAutoConf]);
```

Import `maybeRefreshOpenRouterModels` from the new file. No other changes in
this file.

### B4. Out of scope (explicitly skipped)

- Server-side micro-cache for OR `/v1/models` - the call is small and once per
  browser per 24h; revisit only if load becomes an issue. Avoiding this keeps
  `listModels.dispatch.ts` edits to a single line.
- "Updated N hours ago" UI in the Models modal - would touch `ModelsWizard.tsx`
  /`LLMOptionsGlobal.tsx`. Defer.
- `window.focus` / `visibilitychange` triggers - one boot check is enough for
  the stated problem.
- Extending TTL to other vendors - explicit user decision: OpenRouter only.

## Commit sequence (each independently rebaseable / revertable)

1. **`feat(openrouter): promote ~-latest aliases as visible stable entries`**
   - Track A1 only.
   - User-visible win, near-zero risk.
   - Files: `openrouter.models.ts`.

2. **`feat(openrouter): hide :free, dated snapshots, and previews when a stable sibling exists`**
   - Track A2 + A3.
   - Files: `openrouter.models.ts`, `listModels.dispatch.ts`.

3. **`feat(openrouter): auto-refresh model list every 24h, with UX Labs opt-out`**
   - Track B1 + B2 + B3.
   - Files: `openrouter.refresh.ts` (new), `store-ux-labs.ts`,
     `UxLabsSettings.tsx`, `ProviderBootstrapLogic.tsx`.

Order chosen so the biggest UX improvement per LOC ships first; commit 3 has no
dependency on 1 or 2 and could land independently.

## Validation checklist

After implementation, before committing:

- `tsc --noEmit --pretty && npm run lint` (per AGENTS.md).
- Manually verify in the running dev server:
  - OR model list in the Models modal contains `~`-prefixed entries near the
    top of each vendor group, labeled with ` · latest`.
  - Visible OR model count drops from ~290 to ~40-60.
  - With `localStorage.app-state` left untouched (so `hashLlmReconfig` gate is
    "satisfied"), reloading the chat after >24h triggers a single
    `llmsUpdateModelsForServiceOrThrow` call to OR (observable via Network
    tab); reloading again immediately after does not.
  - Toggling the new UX Labs switch off prevents the refresh on next boot.
  - User-edited OR models (renamed, hidden, starred) retain their edits after
    auto-refresh (`keepUserEdits: true`).
- Confirm the `app-ux-labs` migration runs cleanly on a profile that has
  version 1 already persisted (new field becomes `true`).

## Open items / explicit non-decisions

- We are intentionally **not** snapshotting the OR API response into a Jest
  fixture for regression testing. A test would couple us to a moving upstream
  list; manual verification + the existing `[DEV]` warning logs in the OR file
  are sufficient for now.
- The timestamp key `or-models-last-fetch` is a plain string in `localStorage`,
  not in any persisted store. To force a refresh during debugging, run
  `localStorage.removeItem('or-models-last-fetch')` in the devtools console.
