# Plan: Enable Generative Diagrams and Generative UIs by Default

## Context

Both features are controlled by two boolean flags in `src/apps/chat/store-app-chat.ts`:

| Flag | Current Default | UI Label |
|---|---|---|
| `autoSuggestDiagrams` | `false` | "Generative Diagrams" |
| `autoSuggestHTMLUI` | `false` | "Generative UIs" |

The store uses Zustand `persist` middleware (`name: 'app-app-chat'`, `version: 1`). Existing users already have these flags persisted as `false` in their `localStorage`; changing the in-code default alone only affects **new/fresh** installs (no existing persisted state). To flip existing users' settings, a versioned migration is required.

---

## Options

### Option A - Change defaults only (minimal, new users only)

**Files changed:** `src/apps/chat/store-app-chat.ts` (2 lines)

Change:
```ts
autoSuggestDiagrams: false,
autoSuggestHTMLUI: false,
```
to:
```ts
autoSuggestDiagrams: true,
autoSuggestHTMLUI: true,
```

**Effect:** New installs (no prior `localStorage` entry) start with both features on. Existing users who already have stored state are **unaffected** - their persisted `false` values override the in-code default.

**Pros:** Absolute minimum change, zero risk to existing users.  
**Cons:** Does not change behavior for anyone who has already run the app.

---

### Option B - Versioned migration (new + existing users)

**Files changed:** `src/apps/chat/store-app-chat.ts` (~8 lines)

1. Change in-code defaults to `true` (same as Option A).
2. Bump store `version` from `1` to `2`.
3. Add migration block `fromVersion < 2` that sets both flags to `true` only if they are still at the old default (`false`) - i.e., the user has never explicitly turned them on before.

```ts
// bump
version: 2,

migrate: (state: any, fromVersion: number): AppChatStore => {
  if (state && fromVersion < 1)
    state.autoTitleChat = true;
  // 1 -> 2: enable generative diagrams and HTML UI by default
  if (state && fromVersion < 2) {
    state.autoSuggestDiagrams = true;
    // Note: autoSuggestHTMLUI is alpha-quality with security implications;
    // omit from migration if you do NOT want to force it on for existing users.
    state.autoSuggestHTMLUI = true;
  }
  return state;
},
```

**Effect:** All users (new and existing) get both features enabled on next app load. Users can still turn them off via Settings > AI tab.

**Pros:** Consistent behavior across all users.  
**Cons:** Silently enables `autoSuggestHTMLUI`, which the UI itself labels as "ALPHA QUALITY" with a security warning (JS/HTML code execution). Worth considering whether to include it in the migration or leave it opt-in.

---

### Option C - Migrate diagrams only, leave HTML UI opt-in

Same as Option B but omit `autoSuggestHTMLUI = true` from the migration block. Generative Diagrams become the default for all users; Generative UIs remain opt-in due to their security/alpha warning.

---

## Recommendation

**Option C** is the most balanced:
- Generative Diagrams are stable and the feature has no security concerns - enabling by default makes sense.
- Generative UIs carry an explicit alpha/security caveat, so keeping that opt-in is safer.

If you also want Generative UIs on by default for all users, use Option B.

---

### File: `src/apps/chat/store-app-chat.ts`

2. Line 173: bump `version: 1` -> `version: 2`.
3. Lines 182-187: add `fromVersion < 2` migration block.
